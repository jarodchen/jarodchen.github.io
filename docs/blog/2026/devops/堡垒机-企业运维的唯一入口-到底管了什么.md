# 堡垒机：企业运维的唯一入口，到底管了什么？

运维人员不能直接连服务器。

这听起来有点反直觉。服务器是运维在管，为什么不能直接连？但如果你在一家有规模的公司待过，就会知道这是硬性规定。想连生产服务器，必须先登录堡垒机，由堡垒机验证身份、检查权限，再代理到目标设备，全程记录操作。

堡垒机就是企业 IT 系统的门卫。所有运维访问都得从它这里过，目标服务器不直接暴露给运维人员。

它的英文叫 Bastion Host，也叫跳板机、运维审计系统。名字不太统一，但干的事情是一样的：**统一入口、身份认证、权限控制、密码托管、操作审计。**

## 为什么需要堡垒机

在规模小的时候，运维直接 SSH 连服务器，密码写在自己的备忘录里，谁也不觉得有问题。

但服务器一多，人一多，问题就来了：

- 谁在什么时候连了哪台服务器，没人知道
- 服务器密码在多少人手里流传，数不清
- 有人误删了数据，事后查不到是谁干的
- 等保、ISO 27001、SOX 这些合规要求，一个都过不了

堡垒机就是为了解决这些问题出现的。它把运维访问全部收拢到一个入口，所有操作在它这里被认证、被授权、被记录。

## 核心作用

### 统一入口

所有运维访问必须经过堡垒机。目标服务器不直接对外开放 SSH、RDP 端口，运维人员只知道堡垒机的地址，不知道服务器的真实密码。

这是最基础的一层：把攻击面收窄到一个点上。

### 身份认证

支持的方式很多：账号密码、SSH Key、动态口令、短信验证码、企业微信 / 钉钉、LDAP / AD，以及双因素认证。

企业里常见的是接入 LDAP / AD，员工离职后账号自动失效，不需要在每台服务器上单独删账号。

### 权限控制

精细到什么程度？

“谁、在什么时间、能访问哪些资产、能执行哪些命令。”

比如张三只能登录测试服务器，不能碰生产数据库。李四能连生产服务器，但不能执行 `rm -rf`。王五只能在工作日 9 点到 18 点之间访问。

这些规则都在堡垒机上配置，不依赖目标服务器本身。

### 账号与密码托管

目标服务器的密码由堡垒机统一托管。运维人员不需要知道真实密码，堡垒机自动登录，还可以定期改密。

好处很直接：密码不再在人员之间流转，离职的人带不走，交接也不用改一堆密码。

### 操作审计

这是堡垒机最重要的价值之一。

所有会话都被记录：SSH、Telnet、RDP、VNC 的操作，执行的命令，传输的文件，数据库访问。支持录屏、回放、关键词告警，甚至命令阻断。

出了问题，可以精确回溯到具体的人、具体的时间、具体的操作内容。

### 合规与追责

等保、ISO 27001、SOX 这些合规要求，几乎都涉及访问控制和审计追溯。堡垒机是满足这些要求的标准手段之一。

一旦发生误操作或数据泄露，审计日志就是追责的依据。

## 工作原理

结构很简单：

```
用户 → 堡垒机 → 目标服务器 / 数据库 / 网络设备
```

堡垒机在中间，作为代理或网关。所有流量和操作都经过它，所以它能认证、能授权、能审计。

用户看到的是堡垒机的界面，实际操作的是目标设备。对用户来说，像是直接连上了服务器；对服务器来说，连接来自堡垒机，不是来自用户。

## 常见形态

**硬件堡垒机。** 传统数据中心常见，一台专用设备，插上网线就能用。

**软件堡垒机。** 部署在虚拟机或物理服务器上，灵活性更高。

**云堡垒机。** 云厂商提供，比如阿里云堡垒机、腾讯云堡垒机。开箱即用，按量付费。

**开源方案。** JumpServer 是比较流行的选择，功能覆盖得不错，社区活跃。

选哪种看场景。传统企业机房偏向硬件，云上业务偏向云堡垒机，预算有限或者想自己掌控的，开源方案也能用。

## 和跳板机、VPN 的区别

这三个概念经常被混在一起，但职责不同。

**跳板机**通常只是一台中转服务器，主要解决网络可达问题。比如内网服务器不对外暴露，先连跳板机，再从跳板机连内网。审计和权限控制比较弱，甚至没有。

**堡垒机**不只是中转，它强调身份、权限、审计、密码托管、合规。跳板机能做的它都能做，跳板机做不了的它也能做。

**VPN** 解决的是远程网络安全接入问题。它像给用户开一条加密隧道，让用户能安全地访问内网。但进来之后能做什么、做了什么，VPN 管不了。

一句话区分：

- **VPN**：让你能进来
- **跳板机**：让你能中转
- **堡垒机**：进来之后，管你能做什么、记录你做了什么

## 一句话总结

堡垒机是企业运维的**统一入口 + 权限闸门 + 操作录像机**。

它防止内部人员越权操作，也让出了事之后能追溯到具体的人。服务器越多、人越多、合规要求越高，堡垒机的价值就越明显。

小团队可能觉得没必要，但一旦规模上去，没有堡垒机的运维体系基本等于裸奔。
